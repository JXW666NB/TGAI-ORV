"""插件 DSL：一份描述，ORV 自己生成各后端代码。

## 要解决的核心矛盾

用户指出得很准：**C 端插件天生绑定某一个后端。**
CUDA C 不可能跑在 Vulkan 上，也不可能跑在国产卡上 —— 这是物理事实，不是设计缺陷。

于是「插件优先 C 端」和「一个文件适配全部后端」直接冲突。解法不是二选一，
而是把插件分成**三档可移植性**，并让系统按后端自动选最好的一档：

| 档 | 形态 | 可移植性 | 速度 | 谁写 |
| --- | --- | --- | --- | --- |
| **A 组合式** | 用已有算子拼（Python） | ✅ 全后端 | 取决于拼法 | 任何人 |
| **B 声明式内核（本 DSL）** | 逐元素/归约/广播的数学描述 | ✅ **全后端自动生成代码** | 接近原生 | 任何人 |
| **C 后端原生** | 手写 CUDA C / GLSL / 厂商语言 | ❌ 只该后端 | 原生 | 专家 |

纪律：**每个后端原生插件（C 档）都必须同时提供一个 A 或 B 档的回退**，
否则该插件在别的后端上是"不存在"，而不是"跑出错结果"。
这与 `PLUGIN_DISPATCH.md` 的能力纪律是同一条。

## B 档：DSL 长什么样

不用发明一门完整的语言 —— 只需覆盖**逐元素 + 归约 + 广播**，这就吃掉自定义算子的绝大多数
（激活、norm、loss、fused epilogue）。

```python
@plugin.kernel("my_silu")
def my_silu(x, y):
    return y == x / (1.0 + exp(-x))
```

* `==` 表示"写回哪个缓冲"（out 参数），不是比较；
* 右侧只能是**受限表达式**：四则、`exp/log/sqrt/tanh/...`、输入元素、标量常量、
  以及归约 `sum/mean/max` 配 axis。

注册时做**静态检查**：形状能否广播、类型是否一致、有没有用不支持的原语 ——
错在注册阶段报，而不是编译出一段跑错的代码。

归约形式：

```python
@plugin.kernel("my_rmsnorm")
def my_rmsnorm(x, w, y, eps):
    ms = mean(x * x, axis=-1, keepdim=True)
    return y == x / sqrt(ms + eps) * w
```

## ORV 怎么生成各后端代码

同一份 IR（受限表达式树 + 循环结构），每个后端有各自的代码生成器：

| 后端 | 生成 | 编译 |
| --- | --- | --- |
| CUDA | CUDA C | NVRTC 现场编译（已具备） |
| CPU | C | 系统编译器；不可用时回退 numpy |
| Vulkan | GLSL compute → SPIR-V | glslangValidator |
| 国产卡 / 自定义卡 | 由该后端的插件决定（OpenCL C / SYCL / 厂商语言） | 厂商工具链 |

**关键点：新后端不必改 DSL，只需实现"从 IR 到本后端源码"的生成器。**
这正是把「加后端」的成本压下来的地方。

## 与「C 优先」的关系

不冲突，且方向一致：

* **同一个后端上**，C 仍然是最快的写法，DSL 生成的也是 C；
* DSL 解决的是"**写一次，多后端可用**"，原生插件解决"**在这个后端榨到极限**"；
* 两者是"广度 / 深度"的分工，不是替代。

生成器插槽存在，并明确标注「未验证」。不得把"设计好了"说成"能用"。
