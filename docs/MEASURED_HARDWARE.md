## 3. 已知会踩的坑（引用数字时容易错的地方）

1. **seq 越长优势越小**：4090 seq512 1.47× → seq2048 约 1.08×；不要把 seq512 的数字说成"通用"。
2. **两侧是否都开 AMP 会改变结论**：V100 的 1.42× 是"两侧都开 AMP"口径；不标口径会被当成 4090 那种口径。
3. **词表大小影响巨大**：vocab 4096 vs 96000 实测差 **2.29×**（0.215 vs 0.493 s）。跨实验比较必须同 vocab。
4. **没有 Tensor Core 的卡上结论会反转**：P100（sm_60）实测 ORV 慢 22~25%，原因是我们反向注意力内核在 48 KB 动态共享内存上限下退化成 BC=16 滑窗版（见 `docs/P100_WHY_SLOWER.md`）。**"ORV 更快"只对 cc ≥ 7.0 成立。**
5. **A10 有微调数据但没有速度比** —— 不要拿 SFT 的 step 时间当 bench 结论。

## 4. 规则（写给以后的我）

* 写"某卡上快 X 倍"时，**必须同时写：seq、batch、vocab、两侧设置、来源文件**。
* 写"支持某卡"时，区分两件事：**能跑**（适配/跑通）与 **实测领先**（有对比数字）。
* 拿不准就写 ⚠️ 未验证，不要凑表。
