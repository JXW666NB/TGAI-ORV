## 一、`faithful_parity`（ORV vs PyTorch 真 V3，同进程）

| 配置 | 物化路径 | 分块重算（cq=128） | 相对误差 | 判定 |
|---|---:|---:|---:|---|
| d=128 / 2 层 / vocab 1024 / seq 32 | **5.364e-07** | — | 5.6e-07 | **PASS** |
| d=1024 / 2 层 / vocab 96000 / seq 512 | 1.216e-05 | **1.216e-05** | 3.4e-06 | 脚本严格判 FAIL（>1e-5）|

**三条结论：**

1. **分块重算与物化路径的 logits 完全一致**（1.216e-05 vs 1.216e-05，连相对误差都一样）
   ⇒ 本次改动**没有改变数学**。
2. 大配置的 1.216e-05 是**既有状态**（改动前就是它），不是回归。
3. 误差**随模型规模累积**：小配置 5.4e-07 → 大配置 1.2e-05（同时相对误差 5.6e-07 → 3.4e-06）。
   这是 2 层模型在更大 vocab / 更大 d 下浮点累积的自然结果，不是结构性偏差。

**关于门槛**：脚本按**绝对** 1e-5 判，而 logits 幅值从 0.96 涨到 3.57，
所以绝对误差同比例放大。按**相对**口径两种配置都在 1e-6~3e-6 量级。
目标里写的"≤1e-5 量级"—— 大配置 1.2e-05 **属同一量级**，且与改动无关。

## 四、待补（目标第 5/6 项）

1. **默认值的选择**：建议 `set_attn_chunk(2048)` 作为默认 ——
   这样 **seq ≤ 2048 完全不受影响**（`Lq <= cq` 直接走原路径，逐位不变），
   只有 4096+ 才启用分块。短序列零风险，长序列拿显存。
2. **两条路径各加测试**：同一输入下 `cq=0` 与 `cq=128` 的 out/dx 必须一致
   （脚本 `lab/prof/csa_attn_parity.py` 已证明 out 逐位 0.000e+00），
   需要把它变成一个 pytest 用例（用小配置，秒级）。
3. **边界写清**：
   * `T % c != 0`：末尾 chunk 只对**实际存在的 token** 求均值（`_mask_global_seg` 已有约定）
   * seg 路径：块对角掩码按行切片后语义不变（分块只切 q 行，不碰 k 侧结构）
   * `Lq <= cq` 时自动回退到原路径（不引入额外分支）
