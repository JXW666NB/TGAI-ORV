# `T.help` 热更新 Wiki 系统设计

> 目标：**引擎自省给出"有什么"，外部词条给出"怎么用、为什么这样用"，两者一一对应。**
> 词条是**数据，不是代码** —— 改文件即生效，不用重装、不用重启进程；插件也能带自己的词条；
> 没有词条的条目**也**能渲染出名字与调用示例，绝不出现空白页。

---

## 1. 四层模型（每层职责互不重叠）

| 层 | 来源 | 谁维护 | 是否可热更 | 内容 |
| --- | --- | --- | --- | --- |
| **L0 清单** | 引擎运行时自省（`dir()`/注册表/`inspect`）| 引擎自动 | 天然最新 | 有哪些 `op/api/kernel/cli/env/plugin`，名字、签名、所属模块 |
| **L1 调用示例** | 由 L0 的签名**机械生成** | 引擎自动 | 天然最新 | `t.mul(x)`、`T.help('op')`、`T.DUO(devices=[0,1])` —— 参数怎么填 |
| **L2 词条文案** | `*.txt` 文件（TXT 协议，见 §4）| 人（朋友/插件作者）| ✅ **文件改完即生效** | 中文/英文说明、注意事项、坑、示例代码、见也 |
| **L3 渲染** | 惰性导入的渲染器 | 引擎 | 不需要 | 终端 / JSON / 离线网页 |

**关键**：L2 **绝不**存进 Python 常量、绝不 `import` 进 `__init__`。L1 永远由引擎现算，
所以词条写错签名也不会误导用户 —— 签名只有引擎说了算。

---

## 2. 一一对应：稳定 ID

**规范键**：`<kind>:<name>`，跨语言、跨版本不变。

```
op:mul                 # 张量算子（t.mul(x)）
api:DUO                # 顶层函数/类（T.DUO）
kernel:cast_f32_to_bf16# 原生内核
cli:--dp               # 命令行参数
env:TG_DP_OVERLAP      # 环境变量
plugin:<pkg>:<op>      # 插件提供的条目（防与他人重名）
```

配套规则：

* `aliases: [multiply, 乘法]` —— 改名前/别名都能命中，**报告里显示规范 ID**
* 引擎侧提供 `id_of(obj) -> "op:mul"`，词条侧 `[ID]` 必须写同一个规范 ID
* 词条写了未知 ID ⇒ **加载时报错**（带文件名与最接近的 3 个候选），不许静默忽略
* 引擎里有、词条里没有 ⇒ **不算错**，走第 3 节的降级渲染

---

## 3. 缺词条时的降级（"绝不空白"）

任何条目在 Wiki 里都应该有位置。渲染顺序：

1. 有词条 ⇒ 完整释义 + 示例 + 分类
2. **无词条**（L2 缺失）⇒ 仍然渲染：
   * **名字**（页面里保留条目，带 `未编写` 徽标）
   * **L1 机械生成的调用示例**（参数怎么填）
   * 签名、所属模块、`since` 版本
   * 一句"帮我们补这一条：`T.help.contrib('op:mul')`"
3. 一个都没有（条目本身不存在）⇒ 明确报"没有这个条目"，并给出最接近的候选

`T.help.missing()` 返回**待编写清单**（按 kind/category 分组，含签名与生成示例）——
这就是给朋友们的**工作看板**，也进 CI（见 §7）。

## 4. 词条文件格式（**TXT 协议** — 定稿，见 `wiki/README_词条规范.txt`）

> 2026-11-21 落地时改成 **TXT** 而不是 Markdown+front matter：
> 写词条的人（含非程序员）用记事本就能写，且不需要理解 YAML。
> 下面这段是**权威格式**；`wiki/README_词条规范.txt` 是给作者的详细说明。

一条词条 = 一个 `.txt`（建议命名 `类型.名字.txt`，如 `op.mul.txt`）：

```txt
[ID] op:mul
[分类] compute
[中文名] 逐元素相乘
[英文名] Element-wise multiply
[作者] 张三

=== 中文 ===
正文（Markdown 风格的轻量标记：反引号、加粗、段落）

=== English ===
Body...

=== 示例 ===
y = a * b

=== 见也 ===
op:matmul
```

规则（加载器与 `scripts/wiki_check.py` 一致，两者互为交叉验证）：

| 项 | 规则 |
| --- | --- |
| 头部字段 | 只允许 `ID / 分类 / 中文名 / 英文名 / 作者`；**必填只有 `ID`**；出现未知字段 ⇒ 报错 |
| 区块 | 只允许 `=== 中文 ===` / `=== English ===` / `=== 示例 ===` / `=== 见也 ===`；未知区块 ⇒ 报错 |
| 编码 | UTF-8 / UTF-8-BOM / **GB18030** 自动识别（Windows 记事本默认存 ANSI，必须兼容） |
| 文件名 | 随意；建议 `类型.名字.txt`；与 `[ID]` 不一致只警告，以 `[ID]` 为准 |
| 语言 | 中文/英文只写一个**合法**（页面显示"暂无英文/暂无中文"），两个都空 ⇒ 警告 |
| 交叉引用 | `=== 见也 ===` 引用**还没有词条**的 ID ⇒ 记为"待写"，**不是错误** |
| 分类 | 必须在 `wiki/_meta.txt` 里；不在 ⇒ 归 `other` 并在 `check()` 里列出 |
| 特殊文件 | `_meta.txt`（分类表）与 `README*` 跳过不解析 |

**引擎自动补全**：每条词条的**调用示例**由 L0 签名机械生成（见 §1 的 L1），
`=== 示例 ===` 只是人写的补充用法；所以**词条缺失或写错签名都不会误导用户**。

**可达性自证**（1.0.16 起）：L0 对每条目记录 `reachable / form / reach_kind / reach_evidence`，
并在 `T.help('op')` 里说明真实调用形式（例如 `a * b`、`a @ b`、`T.matmul(a, b)`、`a.sum()`）。
网页上不可调用的条目不显示假示例，直接给原因与依据；页脚显示 `可调用 N/M`。

## 5. 分类（两轴，够用且不臃肿）

* **kind 轴**：`op / api / kernel / cli / env / plugin` —— 表示"这是什么"
* **category 轴**（决定侧边栏分组）：`getting-started / tensor / model / memory /
  compute / optim / distributed / plugin / debug / compat`

分类表放在 `wiki/_meta.yaml`（可热更，新增分类不用改代码）：

```yaml
categories:
  - {id: distributed, zh: 分布式, en: Distributed, order: 60}
  - {id: memory,      zh: 显存,   en: Memory,      order: 30}
```

未分类条目归 `other` 并在 CI 里标黄（不阻断，但记入报告）。

## 6. 热更新（不重启、不重装）

```
解析顺序（后者覆盖前者，同 id 覆盖记入 shadowed_by 便于排查）：
  1. 包内 wiki/                        （随 pip 安装，只读）
  2. 插件自带的 wiki/                  （§8）
  3. TG_WIKI_PATH 指定的目录（可多个）  （团队共享盘 / 朋友本地草稿）
  4. ~/.tgai/wiki/                     （用户私有覆盖）
```

* **缓存键** = `(绝对路径, mtime_ns, size)`；每次 `T.help()` 先 stat 顶层目录与命中文件，
  变更即重载（整目录重扫 ≤ 几十 ms，条目几百条时足够快）
* `T.help.refresh()` 强制清空缓存
* 网页里显示 `wiki 版本：<内容 sha256 前 8 位> / 生成于 <时间>`，便于确认"我看的是不是最新"
* 主题：`TG_WIKI_DIR` 只影响读；`T.help(open="web", out="wiki.html")` 可导出静态站点给官网预览

## 7. 谁都能补：`contrib` / `check` / CI

* `T.help.contrib("op:mul")`
  * 若已有词条 ⇒ 打印文件路径
  * 若无 ⇒ **生成骨架 TXT 文件**（`[ID]/[分类]/[中文名]/[英文名]` 与四个区块名都已填好，
    正文是待填的 `## 中文` / `## English`），并告诉用户该放哪个目录
  * 这是让"朋友一起写 Wiki"成本最低的关键：**不用先理解 schema**
* `T.help.check()` → `{documented: N, missing: [...], percent: 87.4}`
  * CI 规则（本仓库）：`api:` 与 `plugin:` 必须 100%；`op:` 允许分批，但**每个 op 至少要有
    自动示例**（永远有）；缺词条的 ID 列进 PR 注释
* 文案校验（CI）：`scripts/wiki_check.py`（头部字段/区块白名单/重复 ID/分类归属/中英缺边/交叉引用）、
  未知字段、重复 id、`since` 大于当前版本（说明写的是未来版本）

## 8. 插件怎么被照顾到（用户点名要求）

插件**三种接入方式**，从易到难：

1. **零配置**：只写了 `@register_op("myop")` 之类的注册 ⇒ L0 自动发现 ⇒ Wiki 里出现
   `plugin:<pkg>:myop`，有名字 + 自动生成的示例，缺词条也能看
2. **带词条目录**：插件包内放 `wiki/plugin/<pkg>/myop.txt`（同一套 TXT 协议），并在入口点声明：
   ```toml
   [project.entry-points."tgai_go.help"]
   myplugin = "myplugin.help:WIKI"        # 一个 dict 或目录路径
   ```
   加载器通过 `importlib.metadata.entry_points()` 发现，**不需要**插件被 import 进引擎主路径
3. **完全自定义**：提供一个 `help_provider()` 返回条目列表（用于动态生成的条目，
   例如"某个 DSL 生成的 10 个算子"），同样按 `plugin:<pkg>:<name>` 命名

冲突处理：两个插件声明同一 ID ⇒ **加载期报错**（指出两个来源），不允许后者静默覆盖；
用户目录（§6 第 4 层）可以覆盖任何来源，并在页面上标"本地覆盖"。

## 9. Web 界面（简洁 + 分类妥当）

单文件、自包含、离线：

* 左栏：**按 category 分组的树**（组内按 kind 徽标区分），顶部 kind 过滤胶囊
* 顶部：搜索框（匹配 name/别名/中英文正文，纯前端；高亮命中）
* 右栏：条目详情（中英切换 tab；签名与示例永远是引擎实时生成的，词条正文在下）
* 缺词条条目：显示 `未编写` 徽标 + 自动示例 + 一键复制 `contrib` 命令
* 页脚：wiki 版本/生成时间/词条数与覆盖率
* **无 CDN、无外链**（`grep -E "https?://"` 必须为空，只允许 `file://`）
* `T.help(open="web")` 写临时文件并 `webbrowser.open`；失败只打印路径（无头环境）
* 大仓库友好：条目数据以一份 JSON 内嵌、列表虚拟化到"分组折叠"，1 万条也能 1 秒内打开

## 11. 非目标（写清以免过度设计）

* 不做在线协作/账号体系（朋友们用 Git PR 就行）
* 不做实时文件监听（每次调用 stat 足够，避免线程与跨平台 inotify 麻烦）
* 不把词条塞进 JSON schema 之外的字段（未知字段直接报错）
* 不做自动翻译（机翻进仓库会降低质量；缺一边就如实显示"暂无"）
