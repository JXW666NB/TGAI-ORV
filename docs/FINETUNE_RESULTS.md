## 0. 方法（先定死，避免"事后放宽判据"）

| 项 | 约定 |
| --- | --- |
| **判据** | 留出集 probe loss **下降 ≥5%** 才算"学到"；<5% 记 **未学到**（噪声范围）；上升记 **过拟合/发散** |
| **probe** | 留出集**多条平均**（默认 8 条），训练时**从未见过**；单条噪声 >1%，不可作判据 |
| **覆盖** | 每次评估打印 `probe`，训练 loss 只作参考（样本轮转 ⇒ 每步不可比） |
| **硬件** | A10（Tesla A10，driver 12.4 / NVRTC 12.8，**已修 cubin 加载**） |
| **并发说明** | 24h 长稳同时占用 GPU，SFT 步速从 0.3 s/step 掉到 3~7 s/step —— **这是资源争抢，不是引擎退化** |
| **模型** | Qwen2.5-0.5B-Instruct 官方 safetensors（bf16，本地下载），权重绑定 `tie=true` |

前向先对齐再谈训练（否则一切无意义）：**Qwen2.5 相对误差 4.816e-06**（判据 ≤1e-5，CUDA、官方权重、参考值现场用 transformers 现算）。

## 1. 实验总表

| # | 数据/超参 | 步数 | probe 起 → 止 | 判定 | 结论 |
| --- | --- | --- | --- | --- | --- |
| R1 | persona.jsonl 36 条训练 + 4 留出，lr 2e-5，B=1，S=128 | 30 | 0.9654 → 0.4522（**−53.2%**） | ✅ 学到 | 小样本快速下降；生成 2/3 条人格回答通顺 |
| R2 | 同上 | 300 | 0.9654 → 0.3353（**−65.3%**） | ✅ 学到 | 30→300 步继续降；但生成在域外输入退化为复读 |
| R3 | sft_big 396 条，lr 1e-5，B=1，带 loss mask | 300 | 3.0150 → 3.0126（−0.1%） | ❌ 未学到 | 样本更杂更难，步数不足 |
| R4 | sft_big 2000 条，lr 3e-5，B=1 | 2000（中断@418） | 0.42 → **17.2**（step 100）→ 2.78 → 2.30 | ❌ 发散 | **无 warmup/无裁剪时 lr 3e-5 直接爆** |
| R5 | sft_big 2000 条，lr 2e-5 + warmup 100，B=1 | 1500 | 1.5122(25) → 1.5826(50) → 1.6895(75) → 1.6663(775) | ❌ 变差 | **batch=1 梯度方差太大**：训练 loss 0.4~5.4 震荡，留出集反而升 |
| R6 | sft_big 2000 条，lr 1e-5，B=4，clip 1.0 | 60 | 1.4310(25) → 1.4489(50) | ❌ 未学到 | 步数太少（≈0.03 epoch） |
| R7 | sft_big 2000 条，lr 1e-4，B=4，warmup 20，clip 1.0 | 500 | 2.0040(25) → **1.9746(50)** → 进行中 | ⏳ 进行中 | 目前 −1.5%，待跑完判定 |
| **R8** | **4 条样本 × 100 步（过拟合诊断）** | 100 | 1.1433(step1) → 0.0010(10) → **0.000021(25)** | ✅ **引擎正确** | **决定性证据：梯度/mask/优化器/数据链路全通** |

> R8 是最重要的一条：它把"训不出来"的原因从"引擎坏了"排除掉了。
> 做法借自 PyTorch 调试的标准第一步 —— **先让模型过拟合一个小 batch**。

## 3. 踩过的坑（按代价排序）

| # | 坑 | 代价 | 正确做法 |
| --- | --- | --- | --- |
| 1 | **判据用训练 loss** | 一次误判"FAIL"（其实链路是通的） | 固定探针、多条平均、≥5% |
| 2 | **提示不套训练模板** | 生成全是 `？？？？`，差点误判"模型坏了" | 生成必须用与训练一致的模板 |
| 3 | **batch=1** | 1500 步留出集反而变差 | mini-batch 梯度累加（`--batch N`） |
| 4 | **无 warmup + lr 3e-5** | 留出集爆到 17.2 | 线性 warmup；`--clip 1.0` |
| 5 | **梯度裁剪实现太慢** | 0.3 → 7.8 s/step（每参数 D2H）；改单线程内核更糟（36 s/step） | **并行归约内核**（136M 元素 2.0 ms，2850×） |
| 6 | **`.TG` 布局与 RoPE 混用** | 相对误差 0.44（不报错，纯错） | `.TG` 需反置换，或统一用交错式 RoPE（二选一） |
| 7 | **tie 参数进优化器两次** | 一步 0.98 而非 0.99；裁剪范数 6.93 vs 5.66 | `params()` 按 `id()` 去重 |
| 8 | **按"有没有 lm_head" 判 tie** | 官方 Qwen3 文件带 lm_head ⇒ 被训成不 tie | 以 `config.json` 的 `tie_word_embeddings` 为准，并校验数据相等 |

## 4. 复现命令

```bash
# 前向对齐（先做这个，判据 ≤1e-5）
python tools/qwen25_gpu_parity.py --dir /mnt/workspace/qwen25 --device cuda

# 过拟合单 batch（引擎正确性自检，30 秒）
python examples/qwen25_sft.py --safetensors /mnt/workspace/qwen25 \
  --data /mnt/workspace/sft_big.jsonl --tokenizer /mnt/workspace/qwen25/tokenizer.json \
  --steps 100 --batch 4 --limit 4 --holdout 0 --lr 1e-4 --clip 0 \
  --seq-len 128 --device cuda

# 真实微调（带留出集与裁剪）
python examples/qwen25_sft.py --safetensors /mnt/workspace/qwen25 \
  --data /mnt/workspace/sft_big.jsonl --tokenizer /mnt/workspace/qwen25/tokenizer.json \
  --steps 500 --batch 4 --limit 2000 --holdout 8 --lr 1e-4 --warmup 20 --clip 1.0 \
  --seq-len 128 --device cuda --save /mnt/workspace/qwen25_sft500.npz
```

## 5. 现在能证明什么 / 不能证明什么

**能证明（有日志与判据）**
- 引擎能在 CUDA 上完成真实 0.5B 模型的**前向（4.8e-6 对齐）、反向、优化器更新**；
- 数据链路正确到"可以把 4 条样本过拟合到 loss 2e-5"（R8）；
- 小样本 SFT 能学出人格格式（R2：留出集 −65%，生成 2/3 条通顺）。

**不能证明**
- 训出来的模型"可用"：R2 域外复读、R7 目前仅 −1.5%；
- 更大模型 / 更长上下文 / 多卡 / 真实大规模语料（数千~数万条、1+ epoch）的表现；
- 生成质量的自动评测（目前只有 3 条人工看）。

> 一句话：**"能训"已经证明，"训得好"还没证明。**
