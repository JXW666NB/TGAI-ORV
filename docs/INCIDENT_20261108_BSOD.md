## 判断：**不是 GPU 驱动崩**，是主机内存管理器崩

理由：
* `0x1A` 是 **memory manager** 的 bugcheck；GPU 驱动崩通常是 `0x116`(VIDEO_TDR)、`0x119`、`0xEA`。
* 崩溃点在"反复分配失败 + mmap 大文件 + OOM 异常路径"之后，属于内存管理高压场景。
* 同机 10 月已有两次不同蓝屏 ⇒ **该机器本身存在稳定性历史**，不能全归给本次实验。

## ORV 必须加的保护（据此新增，不是猜测）

1. **禁止反复撞 OOM**：`empty_gpu`/大分配前先 `cuMemGetInfo`，若"申请量 > 可用×0.9"直接抛出**可读错误并退出**，不再由驱动反复返回失败。
2. **训练脚本必须先确认显卡空闲**（<100 MiB 且连续两次），否则不启动。
3. **不在同一进程里混用**：大页 mmap 读 3B 文件 + 大量 GPU 分配 + 异常重试。
4. 事后恢复流程必须幂等（本次 `finally` 只拉起一个实例，需逐端口验证）。
