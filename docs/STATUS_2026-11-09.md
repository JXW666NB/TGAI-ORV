## 5. 踩过的坑（避免重复）

- **不能批量 scp** 这棵树：多文件 scp 在缺文件时会中断，导致远端新旧文件混杂（曾伪装成"循环导入"）。逐个复制并核对 sha256。
- **不要用 PowerShell heredoc 写代码**：引号会被吞（`unterminated string literal`），已多次中招；用 edit/write 工具。
- **计时必须校准**：`rt.zeros` 对"已干净"的池块会跳过清零，导致 128 MB memset 测出 0.000 ms。用 `tools/zeros_check.py` 的对照（memset 0.78 ms / h2d 37.5 ms @4 GB/s）做标尺。
- **GPU 任务串行**：同时跑两个会 OOM（已发生）；GPU 前 `stop.py`、后 `rs3.py`。
- **"看起来等价"最危险**：MoE softmax 作用域、causal mask 两次事故都源于此。改前先写同权重对照。

## 7. A2（CUDA Graph）块级已验证（2026-11-10）

**结论：图形重放与逐算子路径逐位相同，且快 2.9–3.8×。**

分进程验证（`tools/graph_xproc.py`，三个进程互不共享状态）：

```
                 max|.| 逐位一致：q 0.2293  k 0.1931  v 3.586  o 2.546
```

速度（CUDA event 计时，三次独立复现）：**6.5 ms vs 18.8–24.6 ms ⇒ 2.88× / 3.55× / 3.8×**。

### 三条必须记住的坑（都让我误判过）

1. **`np.asarray(t.data)` 拿不到 CUDA 张量的数组**（0 维对象）→ 一律用 `to_numpy()`。
2. **Python 时钟测不到设备工作**（曾把 128 MB memset 测成 0.000 ms）→ 计时用 `torch.cuda.synchronize()`
   或 CUDA event；`rt.sync()` 不可靠。
3. **同一进程里多次训练/计时**会互相污染（多 trainer 并存、池缓冲复用），导致"梯度差 1.62e+01"
   这类假故障 → 做等价性验证要**分进程**。

### 仍未解决

- **逐层**捕获仍被 MoE 的主机往返阻断（`train/__init__.py:4059`）。要真正逐层化，需把 MoE 的
  分组计算改成定形（容量因子 + 掩码）或设备端实现 —— 这会改变数值口径，必须先评估。
- 运行时缺陷：`reserve_capture_arena()` 之后 `empty_cache()` 报 `cuMemFree rc=1 invalid argument`。
  修它要改 `cuda.py`，需用户同意。
- `tools/graph_attn_test.py` 的同进程版本留作对照，**不要**用它下结论。
