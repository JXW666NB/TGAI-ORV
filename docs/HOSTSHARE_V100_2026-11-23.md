# V100 实测：ORV vs PyTorch 的 host（CPU）开销占比

> 实测日期 2026-11-23　｜　Tesla V100-PCIE-32GB（sm_70）｜　Windows 主机
> ORV `tgai-orv 0.9.97`（`D:\orv_pip_0962`）｜PyTorch 侧 `C:\Python311`
> 脚本：`lab/rent/_v100_hostshare3.py`（Job 对象统计整棵进程树 CPU + nvidia-smi 采样）
> 配置：12 层 / d=1024 / E=4 / d_ff=3328 / vocab=96000 / batch=1 / 20 步稳态
> 方法：先跑 2 步做基线，再跑 22 步，相减得到**边际每步**墙钟与 CPU（去掉 import/CUDA 初始化）

---

## 1. 结果

| 侧 | seq | 墙钟/步 | CPU/步（user+kernel） | cpu/wall | GPU 利用率均值 | 自报 step_s |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ORV | 512 | **0.2545 s** | **0.2836 s** | 1.114 | 22.3 % | 0.2615 |
| PyTorch | 512 | 0.3807 s | 0.4227 s | 1.110 | 32.5 % | 0.4019 |
| ORV | 2048 | **0.7298 s** | **0.8109 s** | 1.111 | 45.7 % | 0.7300 |
| PyTorch | 2048 | 0.8673 s | 0.9477 s | 1.093 | 58.2 % | 0.8798 |

**加速比**：seq512 **1.50×**（CPU 比 1.49×）；seq2048 **1.19×**（CPU 比 1.17×）。

---

## 2. 三条结论

### 2.1 两边都是 host 受限，不是 GPU 受限

`cpu/wall ≈ 1.10`（两侧都一样），说明主线程 CPU 时间几乎等于墙钟；
同时 **GPU 利用率只有 22–58%** ⇒ GPU 大半时间在等 host 派活。
这直接证实：在本配置下，**墙钟由 host 端决定**，不是算力。

### 2.2 加速比 ≈ host CPU 之比（这是最硬的一条）

| seq | CPU 比（PyT/ORV） | 墙钟比（PyT/ORV） |
| --- | ---: | ---: |
| 512 | 0.4227 / 0.2836 = **1.49** | 0.3807 / 0.2545 = **1.50** |
| 2048 | 0.9477 / 0.8109 = **1.17** | 0.8673 / 0.7298 = **1.19** |

两条线几乎重合 ⇒ **谁在 host 上省时间，谁就快**，一比一对应。
这就是"ORV 比 PyTorch 快"的真实来源，而不是「纯 C 让 GPU 算得更快」。

### 2.3 ORV 的 GPU 忙时也更少（次要因素，但确实存在）

用 `利用率 × 墙钟` 粗估 GPU 忙时：seq512 ORV ≈ 0.057 s/步、PyT ≈ 0.124 s/步（约 2.2×）；
seq2048 ORV ≈ 0.334 s、PyT ≈ 0.505 s（约 1.5×）。
⇒ ORV 的算子图/kernel 总 GPU 时间也更少。但因为**两边都 host 受限**，这一项当前不影响墙钟，
只有等 host 开销降下去（例如 CUDA Graph 落地）之后，它才会变成主因。

---

## 3. 对 BUG_ATTRIBUTION_2026-11-23 的意义

* 原 BUG 的核心论断（"真正的变量是 host 开销占比"）**得到实测确认**；
* 但需要补一句更准确的话：在 V100 这个量级的卡上，**双方都 host 受限**，
  所以"host 开销之比"几乎就是"墙钟之比"；
* P100 上输 22% 的机制也被这条串起来：卡更慢 ⇒ GPU 忙时变长 ⇒ host 占比下降 ⇒
  我们的 host 优势被稀释，同时我们的 Pascal kernel 质量劣势暴露。

---

## 4. 局限（不得当成结论）

1. **单次测量**（每配置一次基线+一次正式，未做多轮中位）；V100 空闲、无并发任务。
2. GPU 忙时是用 `nvidia-smi` 的 `utilization.gpu` × 墙钟**粗估**（该指标本身是时间窗内的占用比例，
   采样 200 ms，非精确 busy 计数）。
3. ORV 侧版本 **0.9.97**，不是当前 1.0.21；跨版本绝对值不可直接与 README 的 1.0.8~1.0.9 表混用。
4. 未测 P100 / 4090 / 5090 同一脚本，跨卡结论仍是推断。
5. `cpu/wall > 1` 说明有第二个线程在跑（ORV 侧可能是拷贝/GC 线程），未进一步归因。
