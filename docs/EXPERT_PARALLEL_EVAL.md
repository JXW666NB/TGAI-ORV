# 专家并行（EP）可行性评估（2026-11-17，基于 V3 真实参数）

> 用户提出：多卡时按专家切片 —— 8 卡 8 专家则一卡一专家；2 卡 8 专家则一卡 4 专家；
> 卡数多于专家数时再切专家内部。下面是**按真实参数算出来的**结论，不是估计。

## 一、V3 的参数构成（实测，不是推算）

1 层 = 250,617,985 参数（含嵌入/输出层，它们只出现一次）。按 24 层外推：

| 类别 | 参数 | 占比 |
|---|---:|---:|
| **专家（W1/W2/W3 × E=4）** | **0.981 B** | **65.7%** |
| 注意力/归一化 | 0.315 B | 21.1% |
| 嵌入 | 0.098 B | 6.6% |
| 输出层 head | 0.098 B | 6.6% |
| **合计** | **1.493 B**（5.561 GiB fp32）| 100% |

（与已知的 1,500,681,490 参数 / 5.59 GiB 吻合。）

## 二、EP 每卡要放多少

非专家部分（注意力+嵌入+head = 0.511 B）在 EP 下**仍然全量复制**：

| 卡数 | 每卡专家 | + 非专家全量 | 每卡合计 | 相对单卡 |
|---:|---:|---:|---:|---:|
| 1（现状）| 0.981 B | 0.511 B | **1.493 B** | — |
| 2 | 0.491 B | 0.511 B | **1.002 B** | −33% |
| 4 | 0.245 B | 0.511 B | **0.757 B** | −49% |
| 8 | 0.123 B | 0.511 B | **0.634 B** | **−58%（饱和）** |

**关键结论：收益会饱和在 0.511 B** —— 因为非专家部分是复制的。
要再往下走，必须叠加另外两条轴：
* **词表并行**（嵌入 + head 按 vocab 切）：0.197 B → /卡数
* **张量并行**（注意力/FFN 按 d 切）：0.315 B → /卡数

## 三、ORV 现状：结构对了 80%，但缺两件

**已经具备的条件（这是运气好的部分）**

* 权重是**按专家独立的张量**：`W1[e] / W2[e] / W3[e]`（`v3_moe.py` 里就是 `W1[e]` 这种索引）
  ⇒ "不拥有的专家不分配"是**天然可行**的，不需要拆张量
* 前向已经是「按专家排序取行 → 逐专家算 → scatter_add 放回」的形态
  ⇒ 与 EP 的计算形状完全一致
* 路由（router）是每 rank 都能独立算的轻量部分，可复制

**缺的两件**

| 缺口 | 说明 | 工作量 |
|---|---|---|
| **all-to-all 通信** | `dist.py` 只有 `broadcast` / `all_reduce`；EP 需要"把 token 按目标专家发给对应 rank，再收回来" | 中（可复用现有 shared_memory 传输 + 屏障）|
| **专家子集构建 + 分派逻辑** | 模型只建 `E/world` 个专家；前向按 rank 分桶、发/收、局部算、原路返回 | 中 |

## 四、通信量：EP 比 DP **便宜一个数量级**

| 方案 | 每步通信量 | 说明 |
|---|---|---|
| **DP（已接通）** | **~5.6 GiB**（全参数梯度 all-reduce，bf16 减半也要 2.8 GiB）| 实测过：单卡 2 进程时归约是主要开销 |
| **EP** | **~200 MB**（token 交换；seq512、top_k=2、d=1024、24 层估算）| 每个 token 只发给 top_k 个专家所在卡 |

⇒ 若模型大到必须切分，**EP 比 DP 更省带宽**（差约 28×），这正是 DeepSpeed-MoE 的设计动机。

## 五、对"明天双卡"的实际建议

**1.5B 在单张 32 GB 卡上完全装得下（20.15 GiB，m8v16）** ⇒ 双卡的第一诉求不是省显存，而是**提速**。
* 提速 → **用 DP**（我已接通并验证 gnorm 一致），预期 ~1.8×（不是 2×，因为 DP 有归约开销）
* 想训 **3B+** 才需要 EP
* 双卡 1.5B 用 EP 反而**更慢**：它省显存但不提高吞吐（每卡仍跑完整 batch 的前向）

**所以顺序建议**：先 DP 拿到双卡吞吐；等要上 3B+ 的模型时再做 EP（那时收益才兑现）。

## 六、若要动手做 EP，第一步该做什么（可验证、可回退）

1. 在 `dist.py` 加 `all_to_all(send_bufs, recv_bufs)`（复用现有 shared_memory 槽 + 屏障）
2. 加 `DataParallel` 之外的 `ExpertParallel` 类：管"我拥有哪些专家"与 token 收发
3. `v3_moe` 的前向增加一条 EP 分支：按拥有关系分桶 → 收发 → 局部算 → 收回
4. **验收**：world=1 时结果必须与现状**逐位一致**；world=2（单卡 2 进程）时梯度/权重与
   "同一 batch 不切分"的结果在 1e-6 内一致
