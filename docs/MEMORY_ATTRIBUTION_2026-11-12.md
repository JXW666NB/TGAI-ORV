# 显存归因：差距几乎全部来自"没开检查点"（2026-11-12）

> 起因：社区反馈「ORV 快 1.79×、显存多 1.89×」。
> 方法：`tools/mem_breakdown.py`，两边**同一份 numpy 权重**、同一 dense 结构、
> 各自独立进程，把峰值拆成「权重 / 梯度 / 优化器 / 其余（激活+工作区）」。

## 1. 配置与结果

D=1280 / L=12 / NH=10 / dh=128 / FF=5120 / S=1024 / B=4，fp32，**含 AdamW 一步**。

### 不开检查点

| 类别 | ORV | torch |
| --- | --- | --- |
| 权重 | 1.477 GiB | 1.477 |
| 梯度 | 1.477 | 1.477 |
| 优化器（AdamW m,v）| 2.954 | 2.954 |
| **其余（激活+工作区）** | **13.671** | **2.254** |
| **峰值** | **19.579** | **8.163** |
| 比值 | — | **2.40×** |
| 每层激活 | 1.14 GiB | 0.19 GiB |

### 开检查点（每层 `T.checkpoint` / `torch.utils.checkpoint`）

| 类别 | ORV | torch |
| --- | --- | --- |
| 权重+梯度+优化器 | 5.908 GiB | 5.908 |
| **其余（激活+工作区）** | **2.108** | **1.649** |
| **峰值** | **8.017** | **7.557** |
| 比值 | — | **1.06×** |

## 2. 三条结论

**① 权重、梯度、优化器三类的字节数两边**完全一样**（1.477 / 1.477 / 2.954）。
差距 100% 落在"激活+工作区"这一类 —— 不是存储布局、不是优化器实现。**

**② 差距的大小几乎完全由"有没开检查点"决定：**

| 场景 | ORV / torch |
| --- | --- |
| 不开检查点 | **2.40×** |
| **开检查点** | **1.06×** |

社区看到的"显存多 1.89×"属于前一种。**开检查点后只剩 6%** ——
因为 0.9.53 把检查点修到与 PyTorch 同语义（每层反向峰值 1.68 → 0.117 GiB）。

**③ 因此"ORV 显存多"这个说法要限定：那是"不开检查点"时的行为。**
但更重要的是：**这说明检查点不应该是可选项，而应该是默认做法** ——
同类模型下它把 19.6 GiB 压到 8.0 GiB，代价只是重算。

## 3. 剩余差距（1.28×，激活 2.108 vs 1.649）从哪来

每层多约 38 MB（B=4/S=1024/dh=128）。已知的两个来源：

| 来源 | 量级 |
| --- | --- |
| **SDPA 物化** `[BH,S,S]`：dh=128 ⇒ 低显存内核不生效 | `40×1024×1024×4B = 168 MB`（前向），反向还要 P 与 dP |
| `permute` / `reshape` 在 CUDA 上是**真拷贝** | 每层 q/k/v 与输出各一次，约 3×21 MB + 84 MB |

⇒ 修好 dh=128 的分块融合注意力（见 `ATTENTION_IS_THE_BOTTLENECK_2026-11-12.md`）
会**同时**降这块激活显存并提速，是一石二鸟。

## 4. 该做什么

| 优先级 | 动作 | 依据 |
| --- | --- | --- |
| **1** | **把检查点变成默认**：训练入口/示例一律包 `T.checkpoint`，文档不再写成"可选" | 19.6 → 8.0 GiB |
| 2 | dh=128 的分块融合注意力 | 剩余 1.28× 的主因，且提速 61% 的耗时 |
| 3 | 减少不必要的 `permute`（让 QKV 直接产出 `[B,H,S,Dh]` 布局） | 每层省几十 MB 与几次拷贝 |

## 5. 复现

```bash
python tools/mem_breakdown.py --impl orv            # 不开检查点
python tools/mem_breakdown.py --impl torch
python tools/mem_breakdown.py --impl orv   --ckpt   # 开检查点
python tools/mem_breakdown.py --impl torch --ckpt
```
