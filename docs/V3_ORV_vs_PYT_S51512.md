# ORV vs PyTorch：V3 架构同规模真实训练步对拍（2026-11-13 首版）

> **口径**：两侧都是完整训练步（AdamW、权重真更新、反传），同 batch=1、同 seq、同 step 数、同 vocab。
> **两侧独立随机初始化** ⇒ **loss 不可比**（只作"是否在学"的旁证）。
> **架构尚未完全对齐**，差异见 §3 —— 因此这是"首版"，不是终局数字。

## 1. 配置与命令

| 项 | 值 |
| --- | --- |
| 规模 | d_model=512，8 层，8 专家，激活 1，vocab=4096，seq=512，B=1，5 步 |
| ORV | `tools/v3_orv_train.py --d 512 --layers 8 --E 8 --seq 512 --steps 5` |
| PyTorch | `tools/v3_pyt_train.py --d 512 --layers 8 --E 8 --seq 512 --steps 5` |
| PyTorch 参数量 | 234,161,670（自报） |

## 2. 实测数字（同一张卡、同一时间窗、产线已停）

| 指标 | ORV | PyTorch | ORV/PyT |
| --- | --- | --- | --- |
| 峰值显存（nvidia-smi 采样）| **4068 MiB** | **5349 MiB** | **0.76×** |
| 峰值 − 空载（ORV 330 / PyT 1228）| 3738 MiB | 4121 MiB | **0.91×** |
| 每步耗时（稳态）| 0.43 s | 0.18 s | 2.4× 慢 |
| 吞吐 | 1189 tok/s | 2002 tok/s | 0.59× |
| loss（不可比）| ≈8.39–8.46 | ≈8.41–8.43 | — |

`ln(4096) = 8.32`，两侧都贴着随机水平 ⇒ 初始化正确、没有"假收敛"。

## 3. 架构差异（读数字前必须知道）

| 项 | ORV | PyTorch |
| --- | --- | --- |
| 注意力 | 全 **GlobalAttention** | 部分层 **CSA**（压缩稀疏）|
| 共享专家 | **无** | 1 个（`n_shared_experts=0` 会让参考实现的 `shared_experts` 属性缺失并报错）|
| 路由 | `max+argmax`（CUDA `topk` 未实现）| `topk(s_all+bias)` |
| BlockAttnRes | 无 | 有 |
| 精度 | fp32 | fp32 |

⇒ 记忆方向是可信的（同规模、同 seq），但**倍数会随补齐 CSA/共享专家而变**。

## 4. 判读

1. **显存方向对了**：0.76×（绝对值）/ 0.91×（扣空载）—— 在"必须 ≤ PyTorch"这条红线上是合格的。
2. **速度明显落后**：2.4× 慢。这与 ORV 侧的已知缺口一致：
   RMSNorm 是组合实现（非融合）、注意力走物化路径、MoE 分派每步有主机同步
   （`topi.to_numpy()` 与 `np.argsort`）。
3. 下一步优化的**具体落点**（按收益排序）：
   ① 路由的下标计算挪到设备侧或用缓存（现在每层每步一次 D2H）；
   ② RMSNorm 换融合内核；
   ③ 注意力走 `sdpa_lowmem`（dh==64 时可用，本次 dh=128 用不了，需先确认 V3 的 d_k）。
