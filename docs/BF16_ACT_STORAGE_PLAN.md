# BF16 激活存储：设计与实验协议

> 目标：把**保留给反向的激活**用 bf16 存储（读时升 fp32/fp16），拿回显存。
> 依据：V100 无 bf16 算力，但 bf16 **存储**是纯位运算（`cast_f32_to_bf16` 已存在）。
> 现状：`T.device_caps()` 已能探测；`T.precision_policy()` 已默认 `storage='bf16'`。

---

## 0. 先说清楚一个数：bf16 只有 8 位尾数

| dtype | 尾数位 | 相对舍入误差 | 十进制有效位 |
|---|---:|---:|---:|
| fp32 | 23 | ~6e-8 | ~7 |
| **bf16** | **7（+1 隐含 = 8）** | **~2e-3（最坏 2^-9 ≈ 1.95e-3）** | **~3** |
| fp16 | 10（+1 = 11） | ~2.4e-4 | ~4 |

⇒ **把激活存成 bf16 再升回来，误差是 2e-3 量级，不是 1e-6。**
所以「逐位等价」这个验收标准**在这条路上不可能达到**，必须换成
「**训练行为等价**」：跑 N 步，比较 loss 曲线与梯度范数的偏差是否落在可接受范围。

**这也是我一直没动手的原因** —— 不能拿"改完没报错"当成"验证了"。

## 1. 该降哪些张量（按收益/风险排序）

| 候选 | 收益（1.5B/seq512）| 风险 | 建议 |
|---|---|---|---|
| 每层保留的 `ln1/ln2` 输出、`attn` 输出、`hn` | 每层 ≈ 0.38 GiB × 24 = 9.1 GiB 的大头 | 中（误差进反向）| **先试这个** |
| CSA 的 plan 张量（mask/rope 表） | 小（<0.5 GiB）| 低（只读）| 可一并做 |
| 优化器状态 | 已做（`--opt-state bf16`，省 5.6 GiB）| 已验证 | 完成 |
| **权重本体** | 6 GiB → 3 GiB | **高**（master weight 必须 fp32）| **不做**，只可存 bf16 副本供 GEMM |

## 2. 实现位置（最小改动）

只在 **autograd 的"存/取"两处**动，不改任何算子内核：

1. **存**：某个张量如果只被反向读（`requires_grad=True` 但前向不再被别处用），
   在 `Tensor._backward` 注册之后把它的 `_gpu` 换成 bf16 缓冲，并在 `Tensor` 上记
   `_store_dtype='bf16'`。
2. **取**：反向闭包读它之前，先 `cast_bf16_to_f32` 升回 fp32（**每次读都升**，
   不缓存升回来的副本，否则省不下显存）。
3. 开关：`cfg["act_store"] = "bf16" | "fp32"`，默认 `"fp32"`（不改变现有行为）。

关键难点：**哪些张量"只被反向读"** 需要引用计数。ORV 的 `_parents` 是静态元组，
可以在 forward 结束时统计每个张量作为 parent 出现几次、以及是否还被前向的后续算子使用。
**第一步只处理"层边界上的 x"**（每层输入），它天然只被该层及其反向使用 —— 收益就有 ~9 GiB，
而且引用关系最清晰。

## 3. 实验协议（必须先跑，再决定要不要合入）

### 3.1 数值可接受性（决定性）

同一份权重、同一批数据、同种子，跑 **20 步**，两组对照：

* A：`act_store=fp32`（基线）
* B：`act_store=bf16`

记录每步 `loss` 与 `gnorm`，判据：

| 指标 | 阈值 | 理由 |
|---|---|---|
| 末步 loss 相对偏差 | **≤ 1%** | 20 步内 bf16 噪声不应改变趋势 |
| 逐步 loss 的最大相对偏差 | ≤ 3% | 允许单步抖动 |
| gnorm 量级 | 同数量级，无单调发散 | 防止"看起来正常其实在漂" |
| 无 NaN / inf | 必须 | — |

**若不达标：立刻停，改回 fp32 并存档结论**，不要靠调 lr 掩盖。

### 3.2 显存与速度

* 峰值显存（`peak_live`）必须**明显下降**（预期 −6~8 GiB）；
* 步时允许上升（每次读多一次 cast），但要量化：若涨幅 > 15%，
  需要评估"省显存"是否值得（我们目前的瓶颈是 CPU，多一次 cast 就是多一次 Python + 内核）。

### 3.3 回归

* 全套 `pytest` 0 failed（当前 814 passed）
* `lab/faithful_parity.py` 的 logits 误差仍在 1e-5 量级（**不开启** `act_store` 时）

## 4. 我的预判（写下来，便于事后对照）

* **显存**：大概率能省下 6~8 GiB ⇒ 1.5B/seq2048 可能从 OOM 变成可跑。
* **数值**：20 步内大概率仍收敛（bf16 训练在业界是常规做法，但那是**算力**用 bf16，
  不是**只降存储**再升回来；后者等价于给激活加 2e-3 量化噪声，需要实测确认）。
* **速度**：会变慢（每次读多一次 cast），**可能与"省显存"互相抵消**。
  如果实测涨幅 > 15%，这条路的定位应改为"**换更大 seq 的手段**"，而不是"提速手段"。

---

## 5. 与 CUDA Graph 的关系

两者正交，但**不要同时做**：

* `act_store` 改变显存布局与 cast 次数；
* CUDA Graph 要求**地址与形状完全固定**，一旦捕获，`act_store` 的"每次读都新分配升精度缓冲"
  会让图失效（或需要把缓冲做成固定的 arena）。

⇒ 先做 `act_store`（拿到显存结论），再做 CUDA Graph（把 CPU 开销压掉）。
若先做图，`act_store` 必须改成"固定 arena + 原地 cast"才能兼容。
