# 插件系统宪法

> **性质**：本文是**规范性**文档（normative），不是说明。写的是"必须 / 禁止"，不是"大概如何"。
> **效力**：任何改动插件系统注册接口、分派行为、能力契约的提交，必须先改本文；
> 与本文冲突的代码视为 bug，无论它"能跑"。
> **版本**：对应 0.9.46。宪法自身也受版本约束（见 §7）。

---

## 第 0 条 为什么需要宪法

插件系统一旦对外承诺，就会有别人的代码依赖它。**承诺被悄悄改掉，比功能缺失严重得多** ——
缺失是"用不了"，破坏是"昨天能跑今天算错"。

本文把承诺写死，目的是让后续几十轮开发**不能无意或有意地破坏契约**。

---

## 第 1 条 扩展的唯一通道

**1.1** 核心**不得**接受"仅此一次"的特例代码。新增能力一律走插件轴（§2）。

**1.2** 核心可以增长的条件只有一个：该能力**每一步都会走到**、或**决定数值语义**、
或**必须跨后端一致**。三者皆不满足的，必须做成插件。

**1.3** 允许核心为一等公民的清单（白名单，改动需修宪）：
Tensor / autograd / 分派 / 后端抽象 / core ops（GEMM、elementwise、norm、softmax/SDPA、conv）/
优化器基类与 AdamW / AMP / checkpoint / DataLoader / 层与骨架的**基类**。

---

## 第 2 条 六条轴不得随意增减

| 轴 | 语义 | 注册后 |
| --- | --- | --- |
| ① op | 算子 | 立即可用 |
| ② backend | 计算后端 | **需 `activate()`** |
| ③ optimizer | 优化器 | 立即可用 |
| ④ layer | 层 | 立即可用 |
| ⑤ arch | 模型骨架 | 立即可用 |
| ⑥ api | API 兼容层 | **需 `activate()`** |

**2.1** 新增轴必须同时给出：注册 API、能力声明方式、跨后端语义、回退策略、测试门禁。

**2.2** 六条轴的名字与语义**不得**改变。要改就是新轴 + 弃用旧轴。

**2.3** 层次语义（`A 组合式 < B 声明式 < C 原生`）不得颠倒：**低档必须能覆盖高档的缺席**。

---

## 第 3 条 七条不变量（永不破坏）

以下每一条都有对应测试。**任何一条被破坏，视为最高优先级缺陷。**

### 3.1 热路径不得有 Python 逐元素
Python 只允许出现在图构建与调度。逐元素循环必须下沉到原生内核或组合算子。

### 3.2 分派开销 ≤ 1%
实测缓存命中约 627 ns。对单次 >100 µs 的算子可接受；对小算子（~15 µs）占 4.2%，
**必须用 `plugin.bind()` 静态绑定**。

> 若某次改动让分派开销超过 1% 且无法用 bind 规避，则该改动必须回退或改为静态绑定，
> 并在 `docs/PLUGIN_DISPATCH.md` 记录实测数字。

### 3.3 能力不足必须报错，禁止静默退化
没有可用实现时抛 `DispatchError`，并逐条说明每个候选缺什么（缺哪个能力 / 计算能力不符 /
dtype 不符）。**不允许**"挑一个差不多的跑"。

### 3.4 C 档插件必须提供 A 或 B 档回退
原生插件只保证在某后端上正确。缺少回退时，它在其它后端上必须表现为**不存在**，
而不是跑出错误结果。由 `backend="*"` 通配 + 能力检查保证。

### 3.5 注册不得有副作用；有副作用的必须显式激活
②backend 与 ⑥api 会改变进程全局状态（切后端、改 `sys.modules`），
**只能登记，不得在注册时执行**。安装插件不等于同意它改变进程行为。

### 3.6 出式更新的优化器不得用于共享存储参数
`p.data = p.data - ...` 会替换数组、断开视图，导致"权重更新了、视图还是旧值"。
只有声明 `works_inplace=True` 的优化器可用；由 `plugin.require_inplace()` 在
**注册/构造阶段**拒绝。

> 这不是防御性编程，是实测过的真实故障模式：有测试故意执行出式赋值并断言
> `np.shares_memory` 变 false。

### 3.7 插件不得改变核心的数值语义
dtype 提升规则、累加顺序、边界行为（nan/inf/空张量）属于核心。插件**可以更快**，
不可以"更准"或"更省事地不同"。

## 第 4 条 对插件作者的六条承诺

**4.1 已发布的注册接口在 1.0 之前只增不改。** 必须废弃时：先新增替代接口，旧接口保留至少
两个次版本并在文档标注弃用。

**4.2 错误信息必须能指导修复。** 每条 `raise` 的消息必须写清「哪个对象 / 什么条件 / 怎么修」。
这条由 AST 门禁测试强制，不是靠自觉。

**4.3 命名空间不得被污染。** 条件化实现（带 `backend=`/`caps=`）只进分派表，
不进 `T.functional`；无条件实现才挂成属性。

**4.4 重名不得静默覆盖。** 重复注册必须报错；覆盖要显式 `replace=True`。

**4.5 插件之间互不干扰。** 一个插件的注册失败不得留下半成品状态（`_rollback` 语义）。

**4.6 可复现性。** 已加载插件清单带 sha256（`plugin.manifest()`），能复现"当时装了什么"。

---

## 第 5 条 兼容与版本

**5.1** 插件的 `PLUGIN` 声明必须含 `name` / `version` / `api_version`。
`api_version` 的**主版本**必须与引擎 `API_VERSION` 一致，否则拒绝加载。

**5.2** 主版本只在**破坏第 3 条或第 4 条**时递增。加轴、加参数、加能力名不构成破坏。

**5.3** 插件声明的 `ops` 必须真的注册了；声明了 `test_inputs` 的必须能被数值自检。
不允许"声明了但没实现"。

---

## 第 6 条 安全

**6.1 加载原生库 = 执行任意机器码。** 核心**不做**沙箱、**不**校验来源、**不**检查签名。
这一点必须在文档与 API 文档字符串里写明，不得含糊。

**6.2** ⑥api 轴会改 `sys.modules`，必须显式 `activate()`，且**不得覆盖真实现**。
典型例：`torch-compat` 在检测到真 PyTorch 已加载时**拒绝安装**。

**6.3** 核心不得为了方便而绕过 6.1 / 6.2（例如"自动加载同目录下的原生库"是禁止的）。

---

## 第 7 条 宪法自身的修订

**7.1** 修宪要求：说明动机、列出被影响的插件作者、给出迁移路径、加对应测试。

**7.2** 禁止的修宪方式：为了通过某个实现而放宽不变量；
把"未验证"改成"已验证"而不提供实测；
删除某条不变量而不说明替代保障。

**7.3** 本文与 `docs/DESIGN.md` 的关系：DESIGN 描述**现状与路线**，本文描述**不可协商的约束**。
冲突时以本文为准。

---

## 第 8 条 评审清单（改插件系统时必须逐条过）

- [ ] 是否新增了轴？若是，§2.1 五项是否齐全？
- [ ] 是否改变了已发布注册接口的语义？若是，§4.1 的弃用流程走了吗？
- [ ] 是否引入新的静默退化路径？（§3.3）
- [ ] 是否让分派开销超过 1%？（§3.2，须有实测）
- [ ] 是否让某条不变量失去测试覆盖？（§3）
- [ ] 错误信息是否都带「修法」？（§4.2，AST 门禁会查）
- [ ] 是否引入了注册期副作用？（§3.5）
- [ ] 文档是否同步？【未验证】是否被写成了"已支持"？
