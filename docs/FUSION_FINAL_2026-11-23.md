## 2. 三项任务的最终答案

### 2.1 F1 —— 成功，且是唯一真正"减发射又减流量"的一项

* 发射/步 3073.5 → 2893.5（−5.9%）；中间缓冲流量 −0.10 / −0.24 GB/步
* 逐位一致：336 组 micro（196 支持形状 `max_abs=0` 且 fp32 位模式相同；140 不支持形状正确回退）
  + 确定性 4 步逐字符相同
* 性能 −0.77%（F1）/ −1.18%（F1+ACC）
* **重要教训**：首版"全形状覆盖"是负收益（+0.77%），`fuseb_ax8` 在 `(1024,1024)→(1024,1)`
  上把 GPU 233 µs → 413 µs；加回退阈值后才转正

### 2.2 F2 —— 分析后判定不可做

* 基数：`zeros` ≈ **219 次/步**（脚本打点，20 步差量）
* 来源：`scatter_add_rows` 140 + `index_scatter_add` 117（原子散射需零初值）+ `rmsnorm_bwd` 31 + `moe_scatter_pairs` 15
* **不可行**：同一内核里"先清零再原子加"跨 block 有竞态；"预清零缓冲池"归还后仍要重新 memset
* 上限估算 3.7–4.8 ms/步（1.7%–2.2%），但**安全实现拿不到** ⇒ 不再投入

### 2.3 F3 —— 实现正确但收益为负

* 实现：`cuda.add_multi()` + `fused_add_multi(_v4)`，按原顺序折叠
  （`((x+y0)+y1)…`，与连续 `add_` 的 `__fadd_rn` 序列同）⇒ 确定性 4 步**逐位一致**
* 挂点：`_backward_cuda` 拓扑循环的 `grads.get(id(node))`（唯一权威时刻）
* 性能：0.2209 → **0.2223（+0.6%）** ❌ —— 逐节点 flush 的 Python 记账 + 指针数组上传 ≥ 省下的 366 次发射
* 若将来要救：把 flush 从"逐节点"改成"批量"，把 Python 侧摊薄

## 3. 为什么 8% 不可达（核心证据链）

### 3.1 五项主机侧优化叠加只到 −2.5%

同会话、同基线、3 轮中位：

| 配置 | s/步 | 相对 |
| --- | ---: | ---: |
| 全部关闭 | 0.2207 | — |
| POOL_FAST | 0.2169 | −1.7% |
| LAUNCH_TMPL2 | 0.2184 | −1.0% |
| LAUNCH_LEAN | 0.2179 | −1.3% |
| FUSE_BCAST_ACC | 0.2182 | −1.1% |
| **五项全开** | **0.2152** | **−2.5%** |

单项之和 ≈ −5%，合计 −2.5% ⇒ 打在同一瓶颈、互相重叠。

### 3.2 D2H 不是突破口（微基准纠正）

| 操作 | 空闲 GPU 实测 |
| --- | --- |
| `d2h` 8 KB | **13.6 µs** |
| `d2h` 2 MB | 440 µs（≈带宽极限）|
| `h2d` 4 KB（pageable）| 16.2 µs |

cProfile 里 `d2h` 1.9 ms/次是**队列排空等待**（等已排队的 GPU 工作），不是拷贝开销。
⇒ pinned 通信/批量化只能省微秒；也解释了 `TG_MOE_DEV`（D2H 26→14、CPU −21%）墙钟为何 +1.7%。

### 3.3 天花板的结构性原因

* 每步 2893–3071 次发射，每次 Python 固定开销 ~14 µs ⇒ 约 40 ms/步
* 每步 3501 次分配 + 4680 次 Tensor 包装 ⇒ 约 12 ms/步
* 剩下的主机时间在算子包装、形状检查、梯度累加等固定成本
* **要省 8%（≈17 ms）只能把发射次数砍掉 ~40%** —— 而这要求把跨算子的链合并成更少内核
  （整层融合），必然改变浮点累加顺序 ⇒ 与"逐位一致"判据冲突

### 3.4 与 PyTorch 的对照（同配置、多次稳定）

| 侧 | seq512 | seq2048 |
| --- | ---: | ---: |
| ORV（1.0.25 五项全开）| **0.2152 s** | 0.7185 s |
| PyTorch eager | 0.384 s | 0.858 s |
| 加速比 | **1.78×** | 1.19× |

## 4. 若要继续，只有三条路（都需要重新定义判据或范围）

1. **放弃逐位一致，改 1e-5 相对误差** → 可做整层融合（RMSNorm+RoPE+QKV、SiTU-GLU 链），
   预期 10–15%，属新算子开发（按周计）
2. **保持逐位一致，但换测量尺度**：在 GPU-bound 配置（seq2048、1.5B 真配置）上重新定标，
   那里融合的收益才可能显现（当前 seq512 是 host-bound，利用率仅 25%）
3. **不改代码，换硬件/批大小**：更大 batch、更高带宽的卡（A100 80 GB 可装下 CUDA Graph 的 46 GiB）
