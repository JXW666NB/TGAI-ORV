## 一、我们（ORV）自己的问题：4 条，全部认

### ORV-1（严重）：`T.set_policy("memory")` 之前是**假的**

`_POLICY_PRESETS` 里写着 `attn="flash"`，但**没有任何代码读 `attn` 这个键**
（真正生效的只有 `cache_masks` / `attn_tile` / `fused_rope`）。
所以 `set_policy("memory")` 只改了一个 tile 数值，**注意力路径不变、显存不会降**。
`checkpoint` / `inplace_acc` 两个键同样是死键。

⇒ **你们的 README 里写"POL=memory 省显存"是我们的锅**，之前并不成立。
**已修**：`attn` 现在真的控制路径（`flash`⇔`lowmem=True`），
`standard`/`speed` 保持 `auto`（不给老用户引入回归），`extreme`/`memory` 用 `flash`。

### ORV-2（严重，且被你们的数据证实）：`AMP` 不省显存，反而**更占**

你们的实测：默认 fp32 8.43 GB → `AMP=2` **8.80 GB**（+0.37 GB）。

这不是测量误差，是设计：ORV 的 AMP 是**保守路线** ——
master weights 始终 fp32、激活/中间量也保持 fp32，只把 **GEMM 输入** cast 成 fp16，
而且会额外维护一份 **fp16 权重影子缓存**（`weight_cache=True`）。
所以它是"算力优化"，**不是显存优化**；影子缓存还会净增显存。

⇒ 我们之前把它当作"能省显存的一档"是错的，已在文档里改正。
**要在 P100 上省显存，只能走激活存储（`TG_BF16_ACT` / `--bf16-act`）与重算（`--grad-ckpt`）这两条路。**

### ORV-3：你们测的两个"开关"一个不存在、一个本来就是默认开

| 你们测的 | 事实 | 结论 |
| --- | --- | --- |
| `TG_CUDA_GRAPH=1` | **这个环境变量在 1.0.17 之后已从代码里删除**（它从来没人读过；图捕获要靠代码调 `graph_arm()`）| "无变化"是必然的，这一行**没有信息量** |
| `TG_LAUNCH_FAST=1` | 真实存在，但**默认就是开**（`cuda.py`：`LAUNCH_FAST_ENV`，默认开）| 设 `1` 等于设默认值 ⇒ "无变化"是必然的；**有信息量的测法是 `TG_LAUNCH_FAST=0`** |

这两条都是"文档/README 给了错误的旋钮"造成的浪费，我们改。

### ORV-4：显存口径不可直接比

| 你们报的 | 实际含义 |
| --- | --- |
| torch `max_memory_allocated()` | 张量**活**峰值（不含 caching allocator 保留块）|
| ORV `peak_live_bytes` | ORV 池里**活**张量峰值（不含池缓存 `peak_bytes`）|

两者**都不等于"16 GB 装不装得下"**（都不含 CUDA 上下文 / cuBLAS workspace / 框架缓存）。
所以 +26%/+37% 这个差额里，有多少是真实占用、有多少是口径差，目前**无法判定**。
公平做法：两边都报三个数 —— 框架 live、框架 reserved/池占用、**`nvidia-smi` 实际占用**。

## 二、你们那份 v3exp2 对照里仍然存在的"不对等"（这几条对我们有利，如实列出）

| # | 不对等 | 方向 |
| --- | --- | --- |
| 1 | ORV 侧 `rope()` 是空操作（`bench_v3exp2.py` L118-120：`return x`），torch 侧是完整模型 | 对 **ORV 有利** |
| 2 | ORV 侧用 `T.nn.MoE(top_k=5, n_shared=1)` 近似 SMS2-MoE，你们注释里写了"ORV 这侧 FLOPs 约高 1.6×" | 对 ORV 不利（但这是**近似导致的**，不是引擎差距）|
| 3 | torch 侧 `m.grad_ckpt = True` 只是挂了个属性，你们模型是否真读它？如果没有，torch 侧**没做重算** | 方向视情况 |
| 4 | ORV 每步内部 `rt.sync()`；torch 只在循环外 sync | 对 ORV 不利（小） |
| 5 | 只 warmup 1 步；ORV 首步含 NVRTC 编译 | 对 ORV 不利（小） |

**所以我不打算争"18% 或 11%"这个数**。真相是：**MoE 层差异 + 口径差 + 编译预热**
三者混在一起，±10% 的差别不足以定性。

## 四、我们最想要的一个数字（比速度更重要）

**显存差距到底来自哪里。** 请在**你们现有的 v3exp2 脚本**里加三行（只读，不改逻辑）：

```python
import os
os.environ["TG_POOL_DEBUG"] = "1"
...
st = rt.pool_stats()
print(st)                      # 总量/峰值/池缓存/命中率
rt.pool_dump_live(top=20)      # 最大的 20 个"活着"的块 —— 这一步是关键
```

`pool_dump_live` 会直接告诉我们：那多出来的 1.7 GB 是
**注意力分数**、**MoE dispatch 缓冲**、还是**某层激活的副本**。
按你们的脚本结构，我猜是 MoE 层（`B*S*top_k*D` 的 dispatch/gather 缓冲，
8 层 MoE × top_k=5）；**但这只是推测，需要那份输出来确认**。

拿到它之后，我们会动代码（MoE 缓冲复用 / 激活存储 bf16 的消费方改造 / 池高水位回收），
而不是继续打嘴仗。

## 五、结论（双方都能接受的版本）

1. **P100 上 ORV 不占优** —— 这张卡没有 Tensor Core，ORV 的加速路径不存在；
   你们"训练继续用 PyTorch"的判断是对的。
2. **主表数字（fp32 vs fp32）成立**；其中 MoE 近似与显存口径使精度不可细究。
3. **显存高 26~37% 是我们需要修的**，不是配置问题（你们已用 AMP 试过、我也确认 AMP 不省显存）。
4. 我们已修：策略 `attn` 死键、删掉幽灵 `TG_CUDA_GRAPH` 文案、把
   `--grad-ckpt-layers` / `--bf16-act` 做成正式开关、启动时对 cc<7.0 的卡明说"不适用"。
5. 下一步要的是 `pool_dump_live` 的输出，然后我们针对 P100 这类卡做显存优化。

## 六、2026-11-21 追加：显存归属已定案（用你回的 pool_dump 数据）

文档：`docs/P100_MEMORY_ATTRIBUTION.md`

```
attn=low    live 5.64  reserved 5.89  nvidia-smi 6.58 GiB   2.15 s/step  1906 tok/s
attn=mat    live 7.73  reserved 8.00  nvidia-smi 8.69 GiB   2.32 s/step  1766 tok/s
差额        +2.09 GiB  +2.11 GiB      +2.11 GiB
```

**结论：** 那 1.7~2.1 GiB 是**物化注意力的分数/softmax/梯度副本**（理论 576 MiB × 2~3 份，吻合），
**不是 MoE** —— 池账本里最大的两类（1.89 GiB / 1.31 GiB）在 low 与 mat 两种配置下**完全相同**。

**因此推翻一个说法**：旧报告"ORV 显存高 26~37%"里，很大一块来自
`bench_p100_full.py` 写死 `lowmem=False`（强制物化），而 torch 的 SDPA 不物化 —— 是**配置不对等**。
在 `lowmem=True` 下，ORV 的 nvidia-smi 占用 **6.58 GiB，低于同脚本 torch 的 6.69 GiB**。

**同时为我自己的两个失误道歉并已修复：**
1. `bench_fair.py` 的 **torch 侧 MLA 形状 bug**（`z @ w` 少了 `.T`）—— 你实测报的
   `mat1 and mat2 shapes cannot be multiplied (4096x1152 and 256x1152)` 就是这个，已修。
2. 我让你把 `pool_dump_live` 放在 **step 之后**，那时注意力中间量已释放，
   所以两种配置都显示 live 4.34 GiB —— 看不到峰值归属。已加 `DUMP_AT=peak`：
   在**第 1 层注意力输出之后**立刻 dump。用法：

```bash
DUMP_AT=peak python bench_fair.py --only orv --bs 2 --attns low,mat --iters 3
```

"ORV 在 P100 上到底是更省显存还是更费显存"。
