feat(core): ParameterGroup works on CUDA via offset views, and clean up the repo root

The earlier claim that this needed a GpuBuf change was wrong. GpuBuf views can carry an arbitrary ptr,
so an offset view costs nothing new: CudaRuntime.sub_view builds one that shares the base allocation,
with view_of holding the parent alive and clearing _token so the destructor does not free it. Out of
range raises rather than silently reading someone else's memory.

Three mistakes only showed up on real hardware. With cuda as the default device, Parameter(ndarray)
immediately made a device copy and left .data as None, so h2d received one element and sub_view reported
an out-of-range offset. I then tried reusing an existing packed._gpu, which read stale content once the
host copy changed. And there was no safe way to load data at all: packed.data = ... is out of place and
severs the views, which is exactly what the charter forbids. Added group.load(), which writes through a
slice and refreshes the device views if already uploaded. self._arr is now documented as the single
authoritative host copy.

V100 results, all exact: pointer offsets correct; views read the right slices (0.0e+00); a view used
directly in a GEMM matches a standalone tensor (0.0); in-place edits to the backing buffer show through.

Separately, the 32 measurement logs sitting in the repository root were mine -- .gitignore covered _*.log
but not bare *.txt. They are the raw evidence behind the numbers in the README and ROADMAP_3B_PERF, so
they moved to docs/measurements/ with an index rather than being deleted, and /*.txt and /*.log are now
ignored.

I also have to record a process failure. I wrote DESIGN.md and the four PLUGIN_* documents without
reading docs/INDEX.md first. The repo already had VULKAN_BACKEND.md, DP_2GPU_RUNBOOK.md,
BACKEND_PORTING.md and PLUGINS.md, and two of my "facts" were false: Vulkan is not zero code -- a
prototype runs bit-exact on an AMD iGPU but is 20-150x slower than numpy because it submits and reads
back per op -- and multi-GPU is not zero code either, there is a runbook with a 1.7x criterion. DESIGN.md
is corrected in five places, INDEX.md now lists the new documents, and DESIGN now carries the lesson:
read docs/INDEX.md before writing anything called a baseline.
