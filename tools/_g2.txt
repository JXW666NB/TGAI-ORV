fix(tests): make two plugin tests resolve a real library path, and drop a stray temp file

The CI failure I had been ignoring turns out to have two causes, and one of them is mine.

test_no_bom flagged tools/_e2.txt, which was a commit-message scratch file. I write those with
Set-Content -Encoding UTF8, which emits a BOM, staged them with git add -A before deleting them, and so
committed one. It is removed from the index now and tools/_*.txt is ignored so it cannot recur.

The other two failures are a genuine portability bug that only Linux could expose. Both tests called
ctypes.util.find_library("msvcrt") or find_library("c") and then handed the result straight to
plugin.load_lib, which starts with os.path.abspath. On Windows find_library for msvcrt usually returns None,
so both tests skipped and the bug stayed hidden. On Ubuntu it returns the soname libc.so.6, which is not a
path, so abspath produced /home/runner/work/TGAI-ORV/TGAI-ORV/libc.so.6 and both tests failed with "native
library does not exist". They now go through a helper that resolves an absolute existing file, trying the
find_library result first and then the usual POSIX library directories, and skip honestly when nothing is
found rather than failing on a path that was never a path.

A side effect worth noting: those two tests now actually execute on Windows instead of skipping, so this fixes
coverage as well as the red build.

Suite: 670 passed / 40 skipped locally, unchanged count, with the two plugin tests moved from skipped to
running.
