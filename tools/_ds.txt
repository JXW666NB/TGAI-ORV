docs: add the long-term design baseline (DESIGN.md)

The project now has a Vulkan backend and multi-GPU ahead of it, both of which will span many rounds, so
the architecture needs one document that later rounds must edit before changing code. Otherwise the design
drifts until nobody recognises it.

Every claim in it carries one of five markers -- measured, implemented, not implemented, design only, or
unverified -- and the doc forbids mixing them. That is the point of the document as much as the content:
several things here look built and are not. Vulkan is zero code. Multi-GPU is zero code. The kernel DSL is
a design with no implementation. ParameterGroup works on CPU and raises on CUDA because GpuBuf has no
offset field. The capacity factor keeps different token sets on CPU and CUDA. Those all appear as debts in
one table rather than being spread across commit messages.

Substantive sections: the four portability tiers that answer how a native plugin survives on Vulkan or a
domestic accelerator (it cannot; it must declare itself absent and let a compositional or DSL fallback
serve that backend); the DSL's restricted form and its S1-S5 staging with S1 not started; what a backend
must implement, including the Vulkan mapping table, where the honest conclusion is that GEMM and
reductions have to be written from scratch so the work is months not days; the interfaces multi-GPU needs
reserved now -- per-device contexts rather than a global singleton, a comms primitive abstraction, and a
redefinition of ParameterGroup views once parameters are sharded; and the measurement and testing
conventions that came from real mistakes, such as measuring one quantity three times as 6.11, 6.42 and
4.18 ms because the first two allocated output buffers inside the timing loop.

Cross-references are checked by tools/check_design_refs.py so the doc cannot point at files that do not
exist.

Version stays 0.9.46: this is documentation only, no code change, so no new release.
