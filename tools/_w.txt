docs: the V100 has no Vulkan because it runs in TCC, and that blocker is Windows-only

The user explained what I could not: the host uses the GT 730 as a display card because the machine has no
integrated graphics, and Windows only permits one NVIDIA driver, so a GeForce driver for the GT 730 and a
data-centre driver for the V100 are mutually exclusive. Measurement confirms the consequence:
nvidia-smi reports driver_model.current = TCC with driver 580.88. TCC is compute-only by design, so Vulkan
cannot initialise on that machine regardless of what is registered.

That retires a suggestion I made last turn. I proposed registering nvoglv64.dll from the driver store as a
Vulkan ICD. In TCC mode that would not help; enabling Vulkan there requires switching the card to WDDM and
installing a driver branch that carries the graphics components, which changes CUDA behaviour and still
collides with the GT 730 driver. The inventory now says so instead of leaving a plausible-looking dead end.

The more useful consequence is that this is a Windows limitation, not a hardware one. TCC exists only on
Windows; on Linux the same NVIDIA driver exposes CUDA and Vulkan together, and Linux is also where dma-buf
external memory lives, which is the more mature path for sharing buffers between devices. So TG Link's P2P
experiments belong on a Linux host with at least two Vulkan devices, and that is now the recommended route
rather than a vague "hardware unavailable".
